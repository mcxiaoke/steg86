# 变更记录 / CHANGES

## 2026-10-18 15:12:09

- **修复 `profile` 在大量真实二进制上直接 Fatal 退出的问题**：原实现对整个 `.text` 做一次性线性反汇编，
  遇到第一条无法解码的指令（`Code::INVALID`）就整体报错退出，导致含有内嵌数据的二进制完全无法使用。
- 根因（实证）：真实二进制会在 `.text` 里混入非代码字节 —— Go 二进制的 "Go build ID" ASCII 串位于
  `.text` 开头（rclone/webdav），MSVC 的 switch 跳转表内联在 `.text` 中（7z）。线性扫描一旦失步即 `INVALID`。
- 修复：`profile()` 改为**跳过 `Code::INVALID` 字节继续扫描**而非 abort；embed/extract 不受影响
  （它们按 profile 给出的有效偏移精确 seek 后单条解码，根本不会扫到数据区）。
- 安全性论证：被记录的候选必须是“特定双指令操作码 + 两个寄存器操作数（mod=11，modRM≥0xC0）”。
  ASCII 文本与小相对偏移跳转表的字节均 < 0xC0，不可能构成误判候选，因此不会把数据误当指令改写而破坏宿主。
  仅对“数据区恰好对齐出现 ≥0xC0 的 modRM 字节”的极少数二进制仍有理论误判风险（线性扫描固有限制）。
- 验证：4 个单元测试通过；rclone(Go)/7z(MSVC)/webdav(Go) 现可正常 profile；对 rclone、7z 做
  embed→extract 往返，消息均正确恢复。

## 2026-10-18 14:57:37

- **优化 release 二进制体积（约 -24.2%）**：release 二进制由 1,305,600 字节降至 989,696 字节。
- 根因：release profile 已很激进（opt-level="z"/lto/strip/panic=abort），体积大头在依赖默认 feature 拉入的未使用代码。
- `iced-x86`：由默认 feature 改为 `default-features = false, features = ["std", "decoder", "encoder"]`，
  去掉全部格式化器（gas/intel/masm/nasm/fast_fmt）、`block_encoder`、`instr_info`、`op_code_info` 等重代码
  （steg86 只做指令编解码，从不格式化输出）。这是本次主要瘦身来源。
- `clap`：改为 `default-features = false, features = ["std", "help", "usage"]`，去掉 suggestions/error-context/color。
- `env_logger`：改为 `default-features = false`，去掉 regex（避免引入整个 regex crate）、humantime、auto-color。
- `goblin`：经实测其 `Object` 枚举被 gate 在 `te` feature 后，且 mach* 强制拉入 archive/endian_fd，
  无法安全裁剪，保留默认 feature（裁剪收益≈0）。
- 验证：4 个单元测试全部通过；对真实 PE 做 profile/embed/extract 往返正确；`--help` 与 `RUST_LOG=debug` 正常。
